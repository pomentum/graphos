graphos

A multi-tenant property-graph service: PostgreSQL + Apache AGE behind a typed HTTP API.

Your services send JSON over HTTP. graphos owns the database, writes the SQL against AGE's tables, enforces tenant isolation, and gives you bulk loading, traversal, aggregation, graph algorithms and a web UI. Consumers never get a connection string.

Get started Benchmarks GitHub

In 30 seconds

  • The problemConnected data turns up in most systems. Once several services need it, each one ends up holding database credentials, its own Cypher, and its own answers to bulk loading, indexing and isolation.
  • The approachOne service owns the graph. Consumers call a typed REST API; graphos alone talks to PostgreSQL + Apache AGE on a private network.
  • What it is notNot a query passthrough for applications (Cypher is offered read-only, under graphos's checks), not a new database engine, and not tied to any domain: graphos ships no labels of its own.
  • LicenceApache 2.0, like the Apache AGE extension it is built on.

03 · BenchmarksBulk writes 37–156× faster than per-row Cypher MERGE

Every write goes through COPY-staged SQL upserts instead of Cypher, every label gets its indexes at registration, and the same graph reads faster on PostgreSQL 18 with AGE 1.8, which graphos now requires. Measured with the scripts in scripts/, by profiling queries and by timing requests against a running service: orders of magnitude, not guarantees.

Factor = before ÷ after; bars on a log scale. Writes: 13k nodes and 44k edges, 4 GB shared_buffers, one host. Lookups: a ~117k-row label. Reads: 251,246 nodes and 940,144 edges, the image's default settings, a laptop, 30 warm runs of 12 reads.
